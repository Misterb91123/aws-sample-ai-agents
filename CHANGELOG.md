# Changelog

All notable changes to this collection are documented here. The format is based on Keep a Changelog, and this project uses date-based releases.

## [Unreleased]

### Added

- Security and guardrails framework in `SECURITY.md`, adapted from the AWS sample-ai-agent-skills SECURITY.md and tailored to these read-only agents (threat model, prohibited recommendations, GREEN/YELLOW/RED safety classification, escalation conditions, anti-hallucination rules, data sensitivity classifications, production deployment recommendations).
- Reusable `## Guardrails` block embedded in all 226 agent system prompts.
- Guardrails checklist and reusable prompt block in `AGENT_TEMPLATE.md`.
- Validation scripts `scripts/validate.py` and `scripts/validate.ps1` enforcing ASCII, JSON validity, required section order, skill frontmatter, and skill reference resolution.
- GitHub Actions workflow `.github/workflows/validate.yml` running validation on push and pull request.
- Issue templates and a pull request template under `.github/`.
- `CONTRIBUTING.md` and `CODE_OF_CONDUCT.md`.
- Least-privilege read-only IAM policy at `policies/agent-readonly-policy.json`.
- Index by AWS service in `CATALOG.md`.
- `version` and `last_updated` fields in every skill frontmatter.
- `INTEGRATIONS.md` showing how to install and configure these agents and skills with AWS DevOps Agent, Claude Code, Kiro, Cursor, AGENTS.md-compatible tools, and any MCP-capable tool, with the read-only posture preserved.
- Structured recommendation handoff: `schemas/recommendation.schema.json` (machine-readable recommendation records with evidence, safety rating, approval and escalation flags, prohibited-action check, and rollback), a Recommendation handoff output contract in `AGENT_TEMPLATE.md`, the read-only remediation-orchestrator agent (227) that safety-gates records into a human-approval-ready change plan without executing, and a Recommendation handoff and remediation section in `SECURITY.md` including the Option 2 execution opt-in and its required controls.

### Changed
- Linked skills to agents: every agent-config.json now references 2 to 4 relevant skills (previously all empty).
- Staggered agent trigger schedules to avoid a thundering herd (clustered cron slots spread across weekdays, hours, and minutes; the largest single cron slot dropped from 73 agents to 4).

## [2026-09-12] - 326 agents, 226 skills across 27 domains

### Added
- Grew the collection to 326 custom agents and 226 skills across 27 operational domains.
- Resilience and chaos-engineering agents (326-330) that turn resilience findings into AWS Fault Injection Service (FIS) experiments, adapted from the awslabs Resilience guidance (guidance-for-enhancing-resilience-devops-agent-fis): fis-experiment-recommender (326, finding-to-FIS-action mapping), fis-experiment-template-generator (327), fis-experiment-safety-and-blast-radius-auditor (328), fis-continuous-chaos-cicd-readiness-reporter (329), and fis-experiment-result-and-resilience-analyzer (330). All read-only and recommend-only: they recommend, template, safety-gate, and analyze experiments and reuse the existing chaos-experiment-planner skill; a human reviews the safety scorecard and runs the experiment. Running an experiment (fis:StartExperiment) is documented in agent-actions/mappings/reliability.md as a special, human-only, RED-by-default action that a scheduled agent never performs.
- DEPLOYMENT.md: a new "Deploying with an AI assistant" section covering Claude (Code and Desktop), Kiro, Cursor, and Amazon Q Developer - both connecting the assistant to the DevOps Agent remote MCP endpoint (Pattern A) and authoring locally then applying through Chat (Pattern B), with per-action approval and read-only posture preserved.
- High-demand diagnostic agents wave 3 (320-325): elasticache-cluster-rightsizer (320), s3-high-volume-deflector (321), athena-partition-doctor (323), and vpc-reachability-connectivity-diagnostic (325). Agent 325 deliberately introduces no new skill - it reuses the existing networking skills (cross-account-connectivity-debugger, nacl-and-sg-conflict-resolution, vpc-route-and-peering-troubleshooting) and adds Reachability Analyzer plus Flow Log REJECT orchestration, honoring the reuse-first principle. This wave completes the "most wanted" build: of the 25 requested items, 5 were already covered (AWS Backup 58, VPN tunnel 128, hybrid asymmetric routing and VPC connectivity skills) and were not rebuilt, and 4 were duplicate entries.

### Removed
- Retired four weak-submission diagnostic agents and their paired skills after applying the Project Nebula "is this skill needed" test (does DevOps Agent already do this natively): 317 ecs-healthcheck-doctor, 318 elb-healthcheck-diagnostic, 322 s3-bucket-hygiene, and 324 unified-security-cost-optimizer, plus skills ecs-healthcheck-mismatch-diagnosis, elb-healthcheck-diagnosis, s3-bucket-hygiene-cleanup, and security-service-cost-optimization. These overlapped native DevOps Agent investigation and cost-optimization capabilities (and an existing load-balancer-health-investigator skill) too closely to justify a public contribution. The 317/318/322/324 numbers are left as gaps rather than renumbering the collection.
- High-demand diagnostic agents wave 2 (313-319): fsx-windows-sla-optimizer (313), datalake-access-analyzer (314, Lake Formation access-denial chain across LF/RAM/IAM/S3/KMS), iam-object-limit-auditor (315, IAM object size/count limits distinct from least-privilege audits), bedrock-capacity-planner (316, capacity vs Service Quotas distinct from the token-cost tracker 108), and aurora-pg-parameter-advisor (319, Aurora-PostgreSQL-specific tuning distinct from the generic parameter-drift auditor 206). Each is read-only and recommend-only with a paired skill and MCP-augmentation guidance.
- High-demand diagnostic agents wave 1 (307-312), built from the highest-volume and highest-time-to-resolution support patterns after a reuse-first gap-check against the existing collection: fsx-ontap-diagnostic (307), aiml-access-doctor (308, a shared AI/ML access-denied chain tracer that emits a minimal least-privilege fix), network-quota-guardian (309, network-scoped quota guard with an opt-in human-approved auto-file directed action), db-connectivity-pathtrace (310, cross-engine DB endpoint-to-client path trace), storage-gateway-health (311, previously uncovered), and eks-node-join-diagnostic (312). Each is read-only and recommend-only with a paired skill, and recommends an AWS or custom MCP server as augmentation where relevant. Items already covered by existing agents/skills (AWS Backup 58, VPN tunnel 128, hybrid asymmetric routing skills, VPC connectivity skills) were deliberately not rebuilt.
- Lambda deprecated-runtime Transform remediation planner (306) and its paired skill (lambda-runtime-transform-remediation, in migration-modernization): starts from the Trusted Advisor Lambda deprecated-runtime check, classifies each flagged function against the deprecation phases with block-deploy deadlines, and plans the code upgrade through AWS Transform (assessment, transformation, verification) with human approval gates at every mutating step and an explicit per-function rollback (previous version for Zip, prior image tag for container-image functions; custom runtimes flagged for a manual base-image path). Read-only and plan-only: a human starts each Transform job, approves each code change, and approves each deploy, and the runtime bump is never applied ahead of the approved, verified code. Complements the runtime tracker (165) and the deadline/roadmap planner (265). The capacity-and-quotas directed-action mapping for the Lambda runtime bump (lambda:UpdateFunctionConfiguration, YELLOW, human-approved) was updated to reflect the Transform-first sequencing and 306 as a source.
- DevOps Agent usage-cost reporter (305) and its paired skill (devops-agent-usage-cost-estimation, in cost-management): answers "what does running AWS DevOps Agent cost me in API usage?" by measuring the downstream, second-order cost on the regular AWS bill. It reads the agent's own call log, isolates the few billed operations (CloudWatch Logs Insights StartQuery dominates at roughly 95 percent; almost everything else is a free Describe/List/Get), prices them live from the AWS Price List API (HALT on an empty lookup, list price treated as an upper bound), and reconciles a bottom-up GB-scanned estimate against Cost Explorer or the CUR. Distinct from the usage-credit monitor (101), which covers direct agent-second usage versus support credits. Read-only and estimate-only; recommends AWS Pricing and Billing and Cost Management MCP augmentation used alongside the direct reads.
- Application-perspective agents (228-255): application performance monitoring (golden signals, end-to-end latency tracing, Apdex, p99 regression, error-signal correlation, memory-leak/GC, dependency SLO impact), release management (DORA four keys, canary/blue-green analysis, change-failure attribution, feature-flag drift, release-readiness gate, post-deploy verification, rollback frequency/MTTR), disaster recovery (RTO/RPO attainment, DR game-day readiness, failover dependency validation, per-application recoverability, active-active drift), site reliability and SLO (error-budget burn rate, SLI coverage, alert actionability/toil, user-journey availability), and application troubleshooting (log-signature clustering, cascading-failure/retry-storm detection, slow-query/N+1, thundering-herd/cold-start, incident timeline reconstruction).
- CloudWatch observability coverage agents (256-261): Application Signals SLO and service map, Lambda Insights performance, cross-account observability (OAM), native metric anomaly-detector coverage, metric-streams and EMF ingestion health, and dashboard coverage.
- End-of-life and extended-support cost agents (262-266): a cross-service extended-support cost-exposure reporter and per-service detectors for RDS/Aurora, EKS, deprecated Lambda runtimes, and legacy EC2 platforms, each with a 60/90/180-day forecast and migration roadmap and estimate caveats.
- Cost-governance and account-contact agents (267-268): cost-protection controls enablement auditor (detect and drive enablement of Cost Anomaly Detection, AWS Budgets, Cost Explorer, RI/SP utilization alerts) and an account alternate-contacts and notification-consolidation auditor.
- Trusted Advisor remediation-and-migration planner (269) and its playbook skill (trusted-advisor-remediation-and-migration-playbook): for every Trusted Advisor check in red or yellow status, complete the recommendation with the validated quantified impact, concrete step-by-step remediation, a safety rating, and a migration path - the next steps Trusted Advisor itself does not provide. Distinct from the trusted-advisor-check-aggregator (226), which aggregates and prioritizes.
- Release-integration agents (290-304) and a new release-integration skill domain (fifteen skills): agents that operationalize and govern AWS DevOps Agent release management when integrated with GitHub, GitLab, and Azure DevOps. CI/CD integration readiness scorecard (290), release-testing coverage and outcomes (291), readiness-review and enablement adoption (292, 304), verification-environment health and cost (293), pipeline IAM/OIDC trust and deploy-permission blast radius (294, 295), artifact and image provenance (296), merge-to-deploy gaps (297), cross-provider deploy flakiness (298), promotion-chain drift (299), IaC change-risk preview (300), pipeline secret exposure (301), post-deploy regression watch (302), and fleet-wide freeze/gate compliance (303). They complement (not reimplement) the native release readiness reviews and release testing. Each agent and skill includes an MCP-augmentation note recommending a relevant AWS MCP server (AWS IaC MCP, AWS Billing and Cost Management MCP, AWS Pricing MCP, Amazon ECS MCP, AWS Documentation MCP, Agent Toolkit for AWS) or a custom MCP where none fits, enabled on the Agent Space and used in addition to telemetry and AWS-infra reads; MCP servers are described in prose only and never added to the tools array. Several extend an existing agent across providers or clouds (298 extends 13; 299 extends 112; 303 extends 282; 294/295 extend 07/49).
- Integration-ecosystem agents (277-289) and a new integrations-ecosystem skill domain (thirteen skills): agents that get more from AWS DevOps Agent integrations. Multi-tool telemetry reconciliation and cost/overlap (277, 278), telemetry coverage and investigation-trigger webhook health (279, 289), cross-provider delivery insight across GitHub/GitLab/Azure DevOps (280 deployment-to-incident correlation, 281 unified DORA), release-freeze and change-collision detection against ServiceNow (282), comms and ticketing hygiene (283 notification routing, 284 ticket/MTTR reconciliation, 285 alert-to-page noise), hybrid AWS + Azure governance (286 inventory/drift, 287 cross-cloud dependency and egress cost), and extension-point security (288 A2A/MCP/webhook health). All read-only; they reason over data the platform surfaces from connected Agent Space associations plus AWS-native reads, and declare no tools outside the validated set. Several extend an existing AWS-only agent across providers or clouds (280 extends 237; 281 extends 235; 285 extends 06/39; 286 extends 225; 287 extends 33).
- Agent-Space memory agents (270-276) and a new agent-space-memory skill domain (seven skills): a new class of agent that leverages AWS DevOps Agent memory. They read the managed stores (understanding-agent-space topology, understanding-dependencies, monitors, directives, reflections) and custom stores to enrich findings with blast radius (270), report topology drift against expected architecture (271), recall per-monitor recurring root causes (272), and audit memory hygiene and limits (276). The curator and librarian agents (273 report-context, 274 known-noise-and-quirks) and the directives-hygiene auditor (275) are recommend-only: they propose memory edits for a human to apply in chat and never write to memory themselves, preserving the read-only-by-default posture for scheduled runs.
- New skill domains (eight): contact-center (Amazon Connect), iot (IoT Core, Greengrass, FleetWise), messaging-deliverability (SES, Pinpoint, Chime SDK), media (AWS Elemental), purpose-built-databases (DocumentDB, Neptune, Timestream, MemoryDB, Keyspaces), agent-space-memory (leveraging the DevOps Agent managed and custom memory stores), integrations-ecosystem (multi-telemetry, cross-provider pipelines, comms and ticketing, hybrid AWS + Azure, and extension points), and release-integration (CI/CD readiness and testing, pipeline trust, IaC risk, and release-management governance, with MCP-augmentation guidance).
- Directed actions (`agent-actions/`): documentation of the AWS DevOps Agent directed-actions model, elevated-role trust and scoped permission policies, a `directed-action.schema.json`, and per-domain mappings of each read-only finding to the exact mutating operation with guardrail status (allowed, refused-delete-class, refused-passrole, refused-prohibited-action), safety rating, approval scope, and rollback. Read-only remains the default; directed actions are opt-in and human-approved.
- Adversarial Input Handling guardrail block (prompt injection, exfiltration, LLMjacking, excessive agency) added to `SECURITY.md`, `AGENT_TEMPLATE.md`, and every agent system prompt.
- Deployment options folder (`deploy/`): a step-by-step quickstart plus Console, AWS CLI, Bash, CloudFormation, CDK, and Terraform guides, and an AI-assistant guide (driving the deploy with, and reusing the skills inside, Kiro, Cursor, Amazon Q, Claude, and Codex).
- Deployment workflow diagram in `README.md` and generator/validation tooling (`scripts/generate_deploy_commands.py`; extended `scripts/validate.py` to check agent tool names and skill `agent_type`, and to skip build output).
